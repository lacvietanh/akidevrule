Bottom line

rtk violates "accuracy over savings" for every command whose output is counted, quoted, diffed or used to claim absence, and upstream offers no lossless mode. Decision: accuracy-first, not abandonment — exclude evidence-bearing commands from the hook rewrite (the only lossless knob for built-in filters), keep recall on with a larger store, never touch filters.toml, and add one verification line for what stays compressed.

Why this was researched

  • rtk 0.50.0 runs as Claude Code's PreToolUse Bash hook (rtk hook claude).
  • Observed 1: ls ~/.claude/agents ~/.claude/skills printed (2 filtered) / [+2 hidden: rtk recall 9393053346b8]. Raw: 20 lines in two labelled groups; filtered: 19 lines, dirs merged, folders first, sizes added. Recall holds only the two header lines — which file is in which dir is unrecoverable. Cause: "unparseable line" path in compact_ls (ls.rs:302-307) + hidden_hint (ls.rs:147-165).
  • Observed 2: jq -c lines cut to 120 chars with ... and [full output: rtk recall 4cb2107f636c]. Cause: built-in src/filters/jq.toml — truncate_lines_at = 120, max_lines = 40. Raw lines 223/217 chars.
  • Owner's standing priority: accuracy over savings. The corpus mentioned rtk nowhere before this research.
  • Method: source of tag v0.50.0, raw (rtk run) vs filtered (hook) runs in a sandbox config/data dir with stdout captured (not a TTY — the shape of Claude Code's Bash tool), upstream issues/docs, HN via Algolia.

Recall in practice

  • Hints: [full output: rtk recall <hash>] (whole output stored) and [+N hidden: rtk recall <hash>] (dropped part only). Store ~/.local/share/rtk/recall.db, gzip sqlite (src/core/tee.rs, src/core/retriever.rs).
  • Stored on success only when something was cut; failures stored when output ≥ 500 bytes.
  • This box: store full at 200 entries, spanning only 2026-10-07..19 (~285 h).
  • Lifetime: 480 elisions, 3 recalls — all 3 made during this research (mark_recalled, retriever.rs:394). Agents do not follow the markers.

How savings are counted

  • README: "up to 90% of the bash output". Tokens = bytes/4 of raw minus filtered (docs/guide/resources/savings-explained.md).
  • dropped content counts as saving; the cost of a re-run, a recall or a wrong conclusion is not counted.
  • phantom saving a head -n N read is booked against the whole file size (read.rs track_bytes(... regular_file_len ...)), though plain head prints the same N lines.
  • This box, rtk gain: 2.6M tokens (50.4%) — rtk read 1.6M, rtk grep 516K, rtk find 66K, then rtk ls: the evidence-bearing families. Phantom vs real split of the 1.6M: unverified.

Claude Code's own limit (vendor docs, not measured)

  • Successful Bash output over ~30,000 chars is saved to a file in the session folder; the model gets the path plus a 2,000-char preview → saves tokens, loses nothing
  • Failed command: only a ~10,000-char head-and-tail excerpt, no path → lossy
  • BASH_MAX_OUTPUT_LENGTH sets the limit (default 30,000, max 150,000). Claude Code's Read/Grep/Glob never pass through rtk.
  • Source: code.claude.com/docs/en/tools-reference "Output limits".

Risk map

unsafe — output is evidence

ls (all forms), find, tree, grep, rg, ast-grep, wc; git diff/log/show/stash show/branch; diff; jq, stat, du, df, ps, ssh; curl/wget beyond the tested case; gh, glab, psql, aws, kubectl/docker logs (untested).

conditionally safe

Test and lint runners (cargo test, pytest, vitest, tsc, eslint): failure list capped at 10–20, only a recall hint marks the rest. When an exact count or the full list matters: RTK_DISABLED=1 <cmd>. Lossless today but brittle: cat/head/tail → excluding costs nothing.

safe to compress

git status/add/commit/push/pull/fetch; package installs (npm/pnpm/pip/uv/bundle/brew install); make (stdout capped at 50, errors on stderr survive but out of order).

Summary

Keep rtk, but never let it touch evidence. Upstream accepts content loss as the price of savings and counts dropped lines as "saved"; agents here followed 3 of 480 recovery hints. The only lossless control is to exclude evidence-bearing commands from the rewrite, which keeps the genuine savings on status, install and build noise. Large output is already handled losslessly by Claude Code itself. Cross-reference: full-file-reads.md — a cat of a rule file is lossless in 0.50.0, and the exclusion makes that independent of rtk's version.
