# Antigravity rule-loader fixes, hidden model table & epistemic floor

Status: Phase A (C1 + C2 + C4) executed 2026-10-28; Phase B (C3 cap remediation) open. Revised 2026-10-26 after a read-only audit and four-round `/akithink` review. This revision replaces the original C1–C4 proposal. It approves corrected loader/model-fact work, narrows the Gemini-only epistemic wording, rejects new universal-core rules, and separates the 24 KB delivery problem from the mechanical fixes.

## Decision

1. **C1 is approved with corrections:** preserve every existing glob pattern, carry the router's complete `Signals` column into Antigravity descriptions, and normalize tilde paths without deleting foreign config entries.
2. **C2 is approved only in narrowed form:** target negative capability claims inferred solely from priors or one tool schema; restore the router's existing `passes no judgment` lookup boundary instead of routing every `how/why not` question.
3. **C3 is split:** adding closed-world text to `agent.B2` or more triggers to `agent.A3` is rejected. The 24 KB problem gets its own implementation gate: trim the always-on `agent` file with headroom, but do not cut 52% of `RULE-release.md` by default. First probe whether generated `model_decision` files can become small frontmatter + canonical-read pointers without changing end-to-end delivery.
4. **C4 is approved with evidence labels:** `agy models` proves the visible list; binary/string and SQLite evidence proves static registration, not successful hidden-model invocation. A transient server enum such as `M322` is not a stable tier contract.
5. **No implementation has been authorized by this document's revision.** Code, installer, runtime config, live `agy -p` probes, and the billed bias suite remain separate execution steps.

## Goal and constraints

**Goal chain:** repair rule delivery → load the right rule at the right time → prevent unsupported negative capability claims and missed analytical routing → reduce wrong decisions and owner reminders → keep one trustworthy corpus across hosts without universal-core bloat.

**Real constraints:** Antigravity 1.4.7 requires comma-separated `globs` strings; every rule file is capped at 24,000 bytes after include expansion; active global/always-on rules also have a 20,000-token aggregate budget; generated descriptions must derive from the canonical router; glob rules need full bodies for deterministic injection; always-on behavior cannot retreat behind a soft read; live model calls require explicit owner authorization because they spend quota.

**Proportionality:** the new Gemini wording reaches every Antigravity turn (estimated reach), so over-broad wording has a larger blast radius than the two observed failures. The cheapest sufficient control is a narrow negative-claim rule plus the existing source-of-truth/verification ladder, not duplicate universal-core text. Installer assertions run once at the generation boundary and cover every install; per-turn defensive wording is not a substitute for them.

## C1 · `install.mjs` — loader and signal delivery

### C1.1 Preserve globs; change only their YAML encoding

`AG_RULE_MAP` remains the source of trigger and glob values. Render the existing values as exactly these two strings, with no pattern removal, addition, renaming, or broadening:

````text
globs: "src-tauri/**, **/*.rs, tauri.conf.json"
globs: "**/*.vue, nuxt.config.*, wrangler.toml, app/**, server/**, composables/**, middleware/**, plugins/**, layouts/**"
````

A useful implementation shape is to store each map entry's globs as a JavaScript array and join it with `", ` at render time, then serialize the complete scalar with `JSON.stringify`. That keeps the source list readable while guaranteeing one YAML string. The acceptance check compares the parsed comma-separated output against the original array element-for-element.

### C1.2 Carry clause + signals through one parser and update both consumers

Replace the clause-only parsing shape with one router parser that returns `{ clause, signals }` for every `RULE-*`/`METHOD-*` row. `agRuleDescription()` uses both fields; the installer summary at `install.mjs:1027-1031` continues to use `clause` only. Do not create a second hand-maintained signal table or leave a summary consumer receiving `[object Object]`.

Every generated non-`always_on` description must contain the semantic clause, the full bilingual concept signals, and the existing imperative to read `~/.aki/akidevrule/<rule-file>`. Signals remain evidence, never a literal gate. Measure generated sizes after the addition; the 24 KB and aggregate-budget constraints still apply.

### C1.3 Normalize `skills.json`; never strip unknown entries

In `updateSkillsJson()`:

- Stop appending a tilde duplicate for the installer-owned `INSTALL_ROOT/agskills` entry.
- Expand only a leading `~/` through the installer's existing home expansion, including legacy `claudedoc` entries.
- Deduplicate by the expanded absolute path, preserving the first entry's other fields and the surviving entries' order.
- Preserve unrelated roots and entry objects. Do not delete an entry merely because it is old, tilde-based, or outside `INSTALL_ROOT`.
- Keep reruns idempotent and keep malformed-JSON preflight atomic.

## C2 · `payload/GEMINI.md` — narrow epistemic and routing boundaries

### C2.1 Add one Gemini-only negative-claim rule in § 7

````markdown
- **No closed-world negative claims:** Pretrained knowledge or one tool's schema alone never proves that a repo, host, or runtime lacks a capability. Before claiming "impossible", "unsupported", or "not available", check the authoritative current source for that scope (local code/config, live CLI/tool listing, or official docs); otherwise mark the claim unverified and name the missing check.
````

This does not forbid disagreement with the owner, does not require a CLI probe for claims already settled by official standards/docs, and does not move concrete model commands or macOS rules into the global file.

### C2.2 Restore the canonical lookup boundary in § 3

Replace the shortened exemption with this meaning: a turn that only reads, counts, locates, or explains what exists **and passes no judgment** loads no contextual rule; the moment it reviews, decides, critiques, or edits, the canonical router and its domain rules apply. Do not add `any how/why not question` as a trigger and do not add a separate Gemini-only taxonomy that can drift from `skills/akirule/SKILL.md` § How to route.

## C3 · Universal core and the 24 KB delivery problem

### C3.1 Rejected: more `agent.A3` triggers

The canonical router already routes evaluation, critique, decisions, and architectural review. Add no owner-pushback phrase and do not broaden `agent.A3(f)` until a post-C1/C2 miss demonstrates a remaining content gap. Reopen on a reproducible miss after the corrected descriptions and lookup boundary are installed.

### C3.2 Rejected: duplicating the epistemic rule into `agent.B2`

`agent.B2`, `agent.B6`, and `coding.B3` already own verified-vs-assumed claims, source precedence, and the verification ladder. C2 addresses the observed Gemini phrasing gap without charging every host and every turn for a duplicate rule.

### C3.3 `agent`: trim the always-on body with measured headroom

`always_on` requires the full body in the generated file. Run a separate subtraction pass on `payload/RULE-agent-behavior.md`; do not append new content during that pass. Target **generated size ≤ 23,500 bytes**, not merely source size < 24,000, leaving 500 bytes before the hard cap. At the current 25,790-byte generated size this requires at least 2,290 bytes removed. Preserve load-bearing behavior and use `coding.B2`/`subtract.B3` before deleting anything. The `agent.A5` path wording is considered only if that pass already edits its sentence; it is not a standalone reason to touch the core file.

### C3.4 `release` and other `model_decision` rules: probe pointer-only generation before rewriting content

Do not schedule a 52% cut of `RULE-release.md`. First establish on Antigravity 1.4.7 whether a `model_decision` rule uses its generated body inline or only its description plus the model's canonical read. If the latter holds, generate these files as frontmatter + a short canonical-read instruction, without the duplicated payload body. This removes the per-file cap exposure and the duplicate copy while preserving the existing read path.

Keep full bodies for `glob` rules because their deterministic file-match injection is the property being repaired. Keep `always_on` full-body delivery as well. Do not emulate a split with `@[label](path)` includes: the vendor cap is measured **after include expansion**, so that shape cannot solve the limit.

If the probe shows that the generated body is required for end-to-end delivery, stop the pointer-only variant and evaluate split independently routed documents versus a real content reduction in a new decision round. No silent rewrite of `RULE-release.md` is authorized by this plan.
